# E5 platform harness

Spec-driven development for the E5 platform, inside Claude Code. It holds the knowledge of the
platform (what each service is for, how a task flows, who owns what), the extractors that keep
that knowledge true to the code, and five commands that use it. It holds **no platform source
code and no credentials**: each person's `/e5-sync` clones the repos with their own login.

## Start

```
git clone <this repo> ~/e5-harness && cd ~/e5-harness
./e5 setup                 # environment, pyright, credentials template, Claude Code plugin
$EDITOR ~/.e5/credentials.md   # GitHub token + JFrog login (never committed, never printed)
claude                     # then:  /e5-init   then:  /e5-sync
```

`/e5-sync` clones every platform repo into `platform/<system>/<repo>`, compiles the Java repos,
runs the extractors and builds the knowledge base. First run: about 1 GB, 15-30 minutes.

## The five commands

| Command | Use it to |
|---|---|
| `/e5-init` | check credentials and tools (changes nothing) |
| `/e5-sync` | clone, compile and rebuild the knowledge from the latest code |
| `/e5-feature` | build a feature: UX + design, blast radius and LLD are each approved before any code |
| `/e5-bugfix` | fix a bug: root cause, blast radius and LLD approved before any code |
| `/e5-update-knowledge-base` | add a service or feature to the knowledge, or record a correction |

## Layout

| Path | What |
|---|---|
| `knowledge/` | the knowledge base: overview, systems, flows, contracts, runbooks |
| `plugin/` | the Claude Code plugin: commands, skills, hooks, MCP tools |
| `tools/`, `extract/` | the extractors, gates and the `e5` CLI's code |
| `catalog/`, `registry.yaml` | the component catalog and the pinned release of each repo |
| `rules/` | semgrep rules that re-check the known issues |
| `graph/` | generated by `/e5-sync`; only the hand-verified citation anchors are committed |
| `platform/` | the cloned platform repos; created by `/e5-sync`, git-ignored |

Tests: `python3 -m pytest tools extract`.
